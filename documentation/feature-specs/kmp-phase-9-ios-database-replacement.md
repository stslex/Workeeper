# KMP Phase 9 — iOS database replacement and crash recovery

**Proposed for maintainer review.** Discovery used [`dev@4884a7a1`](https://github.com/stslex/Workeeper/commit/4884a7a16a8d9327f18fb6a03e9197e675a61102), the merge of [Phase 8, PR #366](https://github.com/stslex/Workeeper/pull/366). Implementation starts after this specification lands in `dev` and Ilya gives explicit GO.

## Outcome and scope

The installed iOS app can replace its local Room database in the same process. A fresh generation reads the replacement. If the app dies during the operation, its next ordinary launch either recovers the correct dataset or opens the DB-independent recovery screen with the evidence preserved. The acceptance test distinguishes two databases with identical schemas by the workouts they contain.

This phase implements the [Phase 8 handoff](kmp-phase-8-permanent-ios-app.md#handoff-and-scope-limits) and the Apple side of the accepted [Phase 5 runtime ownership decision](kmp-phase-5-startup-processor.md#0-decision-record). One implementation PR covers Apple work admission, local replacement, journal replay and simulator evidence. The entry for initiating replacement is internal to the host and exercised with app-owned synthetic snapshots. Normal app startup and Retry use the production preflight. The [Apple Settings backup capability](../../feature/settings/src/iosMain/kotlin/io/github/stslex/workeeper/feature/settings/mvi/handler/UnavailableSettingsBackupHandler.kt) stays unavailable. A backup product, import/export UI, cloud authentication and scheduling need a separate decision. Physical-iPhone workout/media qualification belongs to Phase 10 (T1), and distribution signing, TestFlight and App Store submission belong to Phase 11 (T2).

## Admission and lifetime

1. Inventory reachable Apple DB work before editing. For each entry identify who first resolves the generation, what holds it through the last access, and how retirement drains it. Include direct reads/writes, flow collection, paging loads, cancellation cleanup, post-commit listeners and any process-scoped callback. Generation-parented Store work can use its existing cancel-and-join guarantee. Independent work must acquire a lease at its first operation, before resolving a graph, repository or DAO. Exercise a real direct DAO read through this boundary while no UI grant is held. The background caller must not need to manufacture a UI token.
2. A lease binds one admitted generation until the block, its children and DB-touching cleanup finish. Release it exactly once, including on exception or cancellation. A generation-bound late callback is refused. An independent request that waits through a transition resolves the newly admitted generation, or ends with a bounded unavailable result. Pending recovery admits zero users. A cold flow or pager must have an owner through collection/load. Stop and join a long-lived collector before waiting for its release. Verify production Apple wiring cannot silently choose `DatabaseAdmission.Unrestricted`.
3. Use one process-owned submission path outside Metro for startup, refresh, replacement, compensation, Retry and disposal. A stale submitter cannot replace its successor. Serialize mutating requests with distinct owners and explicit outcomes. Caller cancellation may abandon its wait while the host completes an accepted transaction. Never await the drain from inside a lease the operation itself holds.
4. Close admission before draining exact UI grants and DB leases. Fence late snackbar/media callbacks. Clear the outgoing ViewModel store on Main, cancel and join its lifetime, then close its Room handle off Main. Apply the same ownership order to a partially built candidate. Bound waits and retain ownership on timeout or uncertain close. Graph-only refresh reuses the live handle and bypasses file mutation. File replacement builds a fresh handle, graph, lifetime and ViewModel owner. Publish the fully verified pair once on Main.

## Local transaction and durable state

Follow the [immutable restore protocol](kmp-phase-5-startup-processor.md#273-restore-transaction-and-finalization), [exact rollback ownership](kmp-phase-5-startup-processor.md#274-exact-rollback-ownership) and [terminal publication contract](kmp-phase-5-startup-processor.md#2711-post-review-terminal-publication-closure). `N` is this restore's owner. `P` is an unrelated earlier active undo. A rollback has its own owner and records the exact undo ref it applies.

1. **Stage and validate.** Copy the local source to immutable `RestoreSourceRef(N)` under the app's verified backup-excluded installation directory. Store only validated opaque refs. The dedicated journal must be readable without Room or a serving graph, persist atomic owner-checked edits across process death, and reconcile the existing installation epoch on the envelope and its records. New Apple restore attempts carry their context, source ref and undo ref. Preserve the [process-lifetime DataStore ownership](../../core/data/dataStore/src/commonMain/kotlin/io/github/stslex/workeeper/core/data/dataStore/core/DataStoreProvider.kt) of existing stores. Refuse missing, linked, corrupt, unsupported or non-self-contained input before touching the live database. Use the registered migration path and real SQLite validation. A header or `user_version` alone cannot establish integrity.
2. **Capture the exact pre-image.** Fence writers across the final checkpoint, immutable `UndoRef(N)` copy and handoff to replacement. An acknowledged write made during staging must be present if the app later compensates. Drain readers that can prevent the checkpoint. For a WAL-backed file require the actual `wal_checkpoint(TRUNCATE)` row, zero busy and equal frame counts. For restore, check capacity for the checkpointed live size plus the staged size and a margin before publishing the undo image. For rollback, allow the exact undo size plus the margin. Use overflow-safe arithmetic. Test equality, one byte short, query error and a later write failing with ENOSPC. Restore old admission on a proven reversible rejection. [SQLite WAL](https://sqlite.org/wal.html#the_wal_file) · [Checkpoint result](https://sqlite.org/pragma.html#pragma_wal_checkpoint)
3. **Claim, close and replace.** After reversible quiescence and durable staging, claim `Restore/Prepared(N)` while `P` is intact. The claim can persist even if the write reports failure. From that call onward keep admission sealed until the journal has been reconciled. Retire and close the old generation before replacing `app.db`. Copy the exact staged ref to a fully written, synced temporary in the live directory, perform an atomic rename, then check the parent-directory sync. Account for old `-wal` and `-shm` before installing the new file. A failed close, unsafe sidecar, sync or rename stops the sequence. Immutable refs use no-overwrite publication. A readable path alone proves neither ownership nor durability.
4. **Commit and verify.** Record `Committed(N)` only after durable file replacement. Keep admission closed. Open an existing candidate with the production Room factory and force the first real query, including supported migration. A missing live file during recovery must never become an empty successful install. Use the same owner-checked finalizer for this candidate and for cold-start replay. A live-file swap without a durable commit record can only follow the `Prepared` branch.
5. **Finalize and publish.** In one journal edit, remove the matching attempt, set the active undo and write its terminal outbox. Verified restore activates N, or clears the pointer if N's undo is missing after the restore has been proven. Compensation clears only its applied N and preserves unrelated P. Preserve `UserUndo` versus `ScenarioOneRecovery` terminal semantics. Arm the in-process candidate before handing its pending terminal to the [existing dialog publisher](../../feature/app-dialogs/api/src/commonMain/kotlin/io/github/stslex/workeeper/feature/app_dialogs/api/publisher/AppDialogPublisher.kt). Bind every choice exposed by that terminal to its exact owner, including acknowledgment and any offered local undo. Admit UI/work only after mandatory publication. A failed terminal write leaves replay pending. A failed acknowledgement after successful delivery may replay idempotently. Post-finalization arming failure may retry only on exact finalized proof and cannot trigger a second swap or compensation.
6. **Report and reclaim.** Distinguish rejection before mutation, durable commit (including a later effects error), recovery by rollback, failure after mutation, and failure with no usable generation. Preserve refs required by unresolved attempts, active undo and pending delivery. Sweep only unreferenced protocol-owned files inside the dedicated root after reconciliation. Failed cleanup can retry. Protect the install token, live DB, image files and general preferences.

## Cold start and Retry

Read and reconcile the journal against the local epoch before following any ref. Only a clean ordinary launch may create a new empty database. Preflight may open a specific existing file for validation after classifying the state. Recovery UI and its composition must work without resolving a feature graph. Retry repeats that preflight under the same serialization.

| Durable state at launch | Required outcome |
| --- | --- |
| Fresh install or existing Phase 8 data with no journal, or clean journal with valid pointers and no attempt or pending delivery | Open normally. A first launch after upgrading retains existing workouts, images, preferences and epoch. Unclaimed staging cannot initiate a swap. |
| Foreign epoch | Clear only foreign protocol state atomically before decoding refs. Retain same-named local files and ordinary preferences. Continue ordinary schema preflight. |
| `Restore/Prepared(N)`, including death after rename | Treat the live-file outcome as unknown. With usable `UndoRef(N)`, atomically claim compensation under a fresh rollback owner and restore that exact pre-image. Preserve P. Refuse a “restore succeeded” terminal even if the live DB opens. |
| `Restore/Committed(N)` before finalization | Verify the owned staged source and the existing live candidate. On success finish the N-or-null pointer and outbox transition once. A failed candidate can compensate only from valid exact N before finalization. An unusable or missing required source routes to recovery. |
| Prepared or committed rollback | Replay a prepared rollback from its exact ref. A committed rollback verifies the live DB and finalizes by its descriptor and origin, even if its already-consumed source is absent. Cleanup and later relaunch cannot reapply it. |
| Finalized pointer and pending outbox | Replay mandatory delivery for the exact owner. Preserve the finalized data. Reject mismatched owner, pointer or payload. |
| Corrupt same-install journal, unverifiable file/owner, or mandatory finalization pending | Preserve evidence, keep Home and ordinary DB users sealed, show DB-independent recovery and a retryable reason. A new journal, an unrelated undo or a newly created Room file cannot resolve ambiguity. |

## Acceptance on the Apple runtime

Use only a disposable run-owned arm64 simulator and synthetic files. Give datasets A (original) and B (incoming) the **same schema** and disjoint named training/exercise rows. Give P a third distinguishable sentinel. Retain a write acknowledged late in A and make a fresh write after recovery to detect a repeated rollback.

| Proof | Evidence required |
| --- | --- |
| Admission and warm swap | In one PID, hold a direct DB lease through a transition deadline, query through it, and observe zero premature closes or stale graph resolutions. Release it and replace A with B. A fresh generation reads B and excludes A. A waiting independent operation binds the successor. A bounded pre-claim failure can continue on intact A. Verify the [existing same-DB refresh cases](../../app/ios/src/iosTest/kotlin/io/github/stslex/workeeper/app/ios/IosRuntimeTest.kt) still execute. |
| Real process death before commit | On separate runs pause after durable `Prepared` before rename, and after synced rename before `Committed`. The external runner kills the process at each observed barrier. Relaunch the same installation normally. Both recover exact A including the late write, preserve P and report compensation. Verify the second case really installed B before the kill. |
| Real process death after commit | Kill after durable `Committed` and before finalization. Relaunch keeps B, publishes the correct terminal and selects only N as undo. Interrupt or fault terminal delivery/acknowledgement separately. On another launch a post-recovery write survives and the terminal produces a single logical outcome. |
| Failure isolation | Cover busy WAL, failed close/sync/rename, ambiguous journal write, missing exact N with P present, missing live DB, unsupported schema, foreign epoch and failed candidate verification. Check phase, owner/ref, data sentinels, admission and terminal for each. On a verified restore with a missing undo, assert `previousVersionAvailable=false` and a null active pointer even when P exists. Preserve the Phase 8 unsupported-version sentinel. |

Drive the actual local transaction and cold-start code. Use an XCTest-only driver or an isolated instrumented fixture build for deterministic barriers. The shipping app must expose no launch argument, URL or Settings action that can trigger replacement or crash injection. Observe durable writes before an external hard kill, then await exit and record distinct PIDs/launch IDs, same bundle and data container, simulator UDID, run nonce and source tree. On relaunch, check the expected training and exercise through the installed UI, or assert the recovery screen and absence of Home for a blocked case. Between launches leave the app installed and the journal and SQLite files untouched by the runner. A reconstructed object or a pre-seeded journal can cover branches, but only a terminated process exercises the crash windows above. Scope durability claims to the tested process-loss boundary.

Run focused production-positive → compiled failing control → byte-restored positive. Independently bypass first-operation admission, classify the post-rename `Prepared` file as committed, substitute P for N during compensation, and divert a durable commit to the rollback branch. Require the intended test to fail at its lease/data/owner assertion in each case. Stale outputs, build errors and test discovery failures invalidate the control.
