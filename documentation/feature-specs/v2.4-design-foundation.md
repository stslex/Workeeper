# v2.4 — Design foundation

**Status**: Planned
**Stage decomposition**: `documentation/v2-stage-decomposition.md`
**Schema migration**: **none** (UI/Kit-only refactor; data layer untouched)
**Predecessor**: v2.3 Quick start workout (released)

---

## 1. Scope

### In scope

- Dark theme accent migration (one-color change in `AppColors`).
- `AppDimension` spacing scale consolidation (`Padding` → `@Deprecated`,
  callsites migrate to `Space` opportunistically when screens are touched).
- Selection mode redesign across `feature/all-exercises` and
  `feature/all-trainings`: removal of `SelectionTopBar` and `BulkActionBar`
  separate components, filled-card selected state, FAB transform pattern,
  TagFilterRow stays visible during selection.
- Removal of swipe-to-archive in both list features.
- New `core/ui/kit` components: `AppTooltip` wrapper, `AppCheckmarkButton`
  (filled-circle for set completion), `ReorderableList` modifier (drag-to-
  reorder primitive).
- `LiveSetRow` and `LiveExerciseCard` rework: drag-to-reorder, tooltip on
  set-type chip, three-dots menu offset fix, filled-circle checkmark.
- `PlanEditorScreen` migration from `AppBottomSheet` to a dedicated full-screen
  navigation destination.
- `ExerciseDetailScreen` rework: `LargeTopAppBar` with collapsing scroll
  behavior, conditional hero (only when custom image set), grid default plan
  card with set-type chips.
- `ExerciseRow` content extension: footer line "N sessions · in M trainings
  · last Xd ago".
- `AllTrainingsScreen` sort policy: last-trained DESC, never-trained by
  created DESC.
- `ExerciseChartScreen` fixes: tooltip rewrite from subcompose to
  coordinate-based draw, sort-button affordance, footer-stats stack layout
  fix for Russian text overflow.
- `PastSessionScreen`: removal of total-kg metric, structural edit
  (add/remove/reorder sets) with same delete-confirm patterns as live.
- Templates picker (Home `StartWorkoutWidget`) migration from bottom sheet
  to full-screen route with built-in search.
- Set-type label fix: `SetTypeUiModel.DROP` references the correct string
  resource (`set_type_drop`, currently `set_type_failure` due to typo).

### Non-goals (explicitly deferred)

- **Schema changes.** No DB migration. `SetTypeDataModel` enum stays as
  `{WARMUP, WORK, FAILURE, DROP}` — the perceived "duplicate Failure" was a
  string-resource typo, not a schema duplicate. `DROP` remains a valid type
  with corrected label.
- **Search across exercises in the library.** Acknowledged user request,
  scoped to a separate later stage (no DB FTS infrastructure today).
- **Tag color customization.** Acknowledged, deferred to a future stage as
  a standalone product feature.
- **Material You / dynamic color.** Theme toggle behavior unchanged; only
  the dark accent value is touched.
- **Hide-on-scroll FAB animation.** Bottom content padding fix is in scope;
  the dynamic hide is optional polish, deferred unless it falls out of
  reorderable infrastructure cheaply.
- **Universal "delete with archive offer" dialog flow rewrite.** Today's
  `AppConfirmDialog` already has impact-summary support; we reuse it. A
  dedicated multi-stage dialog (delete → "wait, archive instead?") is
  deferred to a later UX iteration.
- **Light theme palette tuning.** Only dark theme is tuned. Light theme
  reads "приятно" per user feedback.

## 4. New kit components

### 4.1 `AppTooltip`

Wrapper around Compose Material 3 `TooltipBox` with sane defaults (plain
tooltip, long-press trigger, dismiss on outside tap).

```kotlin
@Composable
fun AppTooltip(
    text: String,
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit,
)
```

Used at: PR badge (live workout, past session), set-type chip (live workout
+ plan editor), sort/swap button (chart screen), search-or-create field
empty state.

### 4.2 `AppCheckmarkButton`

Filled-circle button replacing the bare `IconButton(Icons.Filled.Check)` in
`LiveSetRow`.

```kotlin
@Composable
fun AppCheckmarkButton(
    isDone: Boolean,
    enabled: Boolean,
    onToggle: () -> Unit,
    modifier: Modifier = Modifier,
)
```

States:
- `isDone=false`: outlined circle, border `accent`, fill `transparent`,
  no inner icon.
- `isDone=true`: filled circle, fill `accent`, inner icon `Icons.Filled.Check`
  tinted `onAccent`.
- Size: `36dp`. Touch target: `48dp` (padding around).

### 4.3 `ReorderableList` modifier + `ReorderableLazyColumn`

Custom drag-to-reorder primitive. No external dependency.

API surface (proposed):

```kotlin
@Composable
fun rememberReorderableState(
    onMove: (from: Int, to: Int) -> Unit,
): ReorderableState

fun Modifier.reorderable(state: ReorderableState): Modifier

@Composable
fun ReorderableLazyColumn(
    state: ReorderableState,
    modifier: Modifier = Modifier,
    contentPadding: PaddingValues = PaddingValues(0.dp),
    content: LazyListScope.() -> Unit,
)
```

Behavior:
- Long-press on item starts drag.
- During drag: dragged row gets `surfaceTier4` background + small elevation
  via `Modifier.shadow`. Other rows animate to make room
  (`Modifier.animateItemPlacement`).
- Release commits via `onMove`. `onMove` fires once at drop, not during
  drag (avoid intermediate persistence churn).
- Cancellable via drag-out-of-bounds (deferred polish — initial impl just
  commits on release).

Used at: live workout exercises list, live workout set rows inside
`LiveExerciseCard`, plan editor set list, past session structural edit.

## 9. Risks

| Risk | Mitigation |
|---|---|
| `ReorderableList` custom impl proves brittle across LazyColumn nesting (live workout has nested lists). | Implementation step 3.3 includes a spike: build on a small isolated screen first; if nested LazyColumn behavior is unstable, fall back to non-lazy `Column` rendering for inner sets list (set count is bounded, no perf concern). Document the choice in tech-debt if compromised. |
| `LargeTopAppBar` + `nestedScroll` interaction with existing paging-based lists. | LargeTopAppBar adoption is per-screen. Each screen is verified before moving on. List screens (5.2, 5.3) keep small top bar — no nestedScroll concern. |
| Tooltip from `TooltipBox` requires Compose Material 3 1.2+ (verify dep version in `build-logic`). | Verify in step 3.1; bump `compose-bom` if needed. |
| `accentTintedBackground` for dark needs hand-tuning to maintain contrast against `surfaceTier1`. | Visual sanity check via dark-theme previews of `ExerciseRow` (selected state) and `ExerciseDetailScreen`. Accept the value before broad migration. |
| Drag-to-reorder on past session: persistence implications if the session is referenced by aggregate queries (PR detection, `lastTrainedAt`). | Reorder is positional, no metric change. Verify PR query is order-independent (it is — `MAX` over all sets). No refactor needed. |
| Snackbar undo for set delete: state consistency if user starts another set deletion before the first snackbar dismisses. | Queue or replace policy: replace (only one undo at a time). Document explicitly in impl. |
