Exercise list, set choice and skip on the watch

Phase 2 turns the watch from a single “current set” terminal into a workout browser: the session’s exercises with progress, any incomplete set of any exercise, and skipping an exercise. The phone stays the only authority; the watch’s choice of exercise and set is its own and is not mirrored to the phone.

Typefaces are the repository’s own TTFs (IBM Plex Sans, Archivo Bold wdth116, IBM Plex Mono), sizes are WearTypography, colors are WearPalette, and the controller geometry is WearControllerScreen.kt. Every frame measures itself; see “How the checks work” at the end. Copy on the watch uses the phone’s existing wording (“Пропустить упражнение”, “Вернуть в сессию”).

Prototype

Tap rows, the exercise name, Sets, Skip exercise, and the edge button. “Swipe back” is the hardware back / right swipe. The prototype opens the way decision D1 leans: on the controller, with the list underneath.

    Decisions for the owner

    Each has a lean; the prototype follows the leans. Nothing here is locked until you say so.

    D1What the app opens on

    The controller of the watch’s selected exercise, with the list one swipe back. The main job on the wrist is logging the set in front of you.

    Always the list: the whole session first, one more tap per visit.

    D2After the last set of an exercise

    Advance to the first exercise in phone order that is neither finished nor skipped (the Phase 1 target rule). The list is one swipe back.

    Return to the list and let the user pick. Costs a tap per exercise for people who follow the plan order.

    D3How a specific set is chosen

    A: a Sets screen, opened from the exercise name at the top or the Sets row at the end of the controller. It shows every set with its values, so you see what you are picking.

    B: swipe between sets. The page indicator needs about 14 dp above the edge button (see the P frame at 192 dp), and a right swipe would mean “previous set” on every page but the first. That is the same kind of back-gesture confusion the 1.52.2 field test hit.

    D4Where Skip lives

    A: an outlined Skip exercise at the end of the controller, then a confirmation whose edge button skips and whose swipe back cancels.

    B: swipe-to-reveal on list rows. It is the Wear M3 pattern for row actions, but it hides the only way to skip behind a gesture. Both can coexist later.

    D5Tapping a finished exercise

    Opens its Sets read-only, with “Edit on your phone”.

    The row is inert.

    D6Tapping a skipped exercise

    “Return to session?”, the phone’s wording; the edge button returns it, swipe back cancels.

    Open its controller with a Return button.

    D7Where the set position shows at rest

    In the time text arc: “2/3 · 10:09”. It costs no row on a 192 dp screen whose value cards already need every dp.

    A header line under the name. It pushes the cards below the fold at font scale 1.24.

    D8What moves the watch’s selection

    The selected set completed anywhere → the next incomplete set of the same exercise. The selected exercise finished, skipped or removed on the phone → the Phase 1 rule. The selection survives process death in the bounded watch cache.

    Re-derive from the Phase 1 rule on every snapshot. Simpler, but it throws away the user’s choice.

    D9Tile and ongoing indicator

    Follow the watch’s selection, so the Tile shows the set you will log next.

    Keep the Phase 1 target. The Tile and the app would then disagree after any manual choice.

    What protocol v2 has to carry

    • Per exercise: id, name, position, exercise type, skipped, and per set: position, type, weight, reps, done. The list needs per-set done flags because sets can now finish out of order; Phase 1’s setOrdinal / totalSets cannot say that, and wearSetScaleSlots assumes sets finish in order.
    • Commands: complete a named set (the existing CompleteCurrentSetRequest already carries performedExerciseUuid and setPosition; v2 accepts any incomplete set) and set or clear skipped.
    • Bounds: the payload grows with the session, so v2 needs an explicit cap (exercises × sets × name length) and PayloadTooLarge must stay reachable.
    • Disclosure: the public policy says the phone sends “only what the watch needs to show the current set”. A whole exercise list is more than that, so the policy text and the Phase 1 clause in product.md change with v2.
    • Sync: the display-only snapshot pushed with the change signal (option B from the sync discussion) fits here. WatchWorkoutReducer.receiveUnsolicited already admits such a snapshot read-only; nothing calls it today.

    How the checks work

    • Fonts: the repository TTFs from core/ui/design-tokens (IBM Plex Sans 400/500/600, Archivo Bold wdth116 with tnum, IBM Plex Mono 400), subset to Latin and Cyrillic with metrics untouched and embedded in this page. Nothing falls back to a system face; the page waits for document.fonts before it measures.
    • Geometry: controller constants from WearControllerScreen.kt: scroll window from 26 dp below the top to 62 dp above the bottom, 16 dp side insets, primary context 128 × 42 dp, value cards 54 dp with the 1.533 weight share, Small edge button. Lists are a flat column with 5.2 % side margins; TransformingLazyColumn morphing is not simulated, so a list row that crosses the circle is reported as morph (a warning), not as a failure.
    • Font scale 1.24 is a model: ×1.28 up to 14 sp and ×1.20 at 16 sp, as fitted on the 192 dp device in the bottom-band study; ×1.18 at 18 sp and ×1.16 from 21 sp are extrapolated. Line heights go through the same curve. Treat every 1.24 result as a prediction.
    • Per frame: each text node’s line boxes are tested against its scroll window and the screen circle (outside the circle = FAIL); clamped text that ellipsizes is a WARN; a numeral that does not fit its box is a FAIL; an element marked “must be visible at rest” that is cut, hidden or clipped is a FAIL. Every readout states how many nodes and boxes it measured, so an empty walk cannot pass.
    • Known negative: switch Set choice to B. The page indicator takes 14 dp from the controller’s scroll window, the value cards stop being fully visible at rest on 192 dp, and the sweep turns red on those frames. That is the must-visible check firing on a real regression, not on a planted one.
    • Found while building: a full-width Sets row and a full-width Skip exercise row at the end of the controller’s scroll put the upper one in the narrow top of the circle, where the bezel cut its corners. They now share one row (Sets plus an icon-only Skip whose name is spoken), which sits in the wide band.
    • Stress fixture: 12 exercises, long Russian names, ten sets, and 999.99 × 999 on the selected set, the protocol maximum.
